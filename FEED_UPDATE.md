# Обновление каталога из CSV 1С-Битрикс

## Временный сервер REG.RU (07.11.2026)

Рабочая папка исходников: `/var/www/www-root/data/app/rr-tac`.
Её `dist/` — результат генерации; веб-корень — `/var/www/www-root/data/www/rr-tac.ru`.
От пользователя `www-root` запускать `node /var/www/www-root/data/app/rr-tac/update-reg-ru.js`.
По умолчанию эта команда НЕ загружает фид: пересобирает сохранённые товары,
проверяет сборку и публикует её с резервной копией. Расписание обновлений не включено.

07.11.2026 по одобрению пользователя разово применён проверенный снимок фида: 67 товаров, 58 в наличии, 9 под заказ. Локальный проект и рабочий сайт совпадают.

Для следующего обновления сначала получить и проверить актуальный CSV. Явная синхронизация — `--sync` с настроенным
`BITRIX_CSV_URL` или `FEED_FILE`. В копии REG.RU встроенный URL очищен.
При ошибке загрузки каталог и опубликованный сайт не меняются; это проверено
сравнением контрольных сумм. Подробности: `deployment/reg-ru/README.md`.
Инструкции `/var/www/html` ниже относятся к прежнему варианту Beget.

## Самый простой ручной запуск на сервере

> **Перед первой загрузкой или после полной очистки сайта:** сначала отдельно разместить `config/roistat.php` как `/var/www/html/config/roistat.php`, затем загружать содержимое `dist`. Файл содержит секрет, поэтому не входит в Git и `dist`. Если формы или Roistat не работают, сначала проверить наличие файла и права чтения для `www-data` (`root:www-data`, режим `640`).

После `node generate-site.js` в папку `dist` автоматически попадают пять служебных файлов: `update-site.js`, `sync-products.js`, `csv-to-json.js`, `generate-site.js`, `verify-build.js`. Нужно, как и раньше, загрузить всё содержимое `dist` в `/var/www/html`. После этого достаточно выполнить:

```bash
cd /var/www/html
node update-site.js
```

`update-site.js` сам скачивает текущий фид, запускает синхронизацию, генерацию, проверку и только после успешной проверки обновляет файлы в `/var/www/html`. Ссылка на фид уже задана в `sync-products.js`; `feed.env` не требуется. Локальная сборка на Windows по-прежнему использует исходные `.html`-шаблоны и не зависит от серверного режима.

## Как работает синхронизация

CSV является фидом доступных товаров, а `assets/data/products.json` — накопительным каталогом сайта.

- товар присутствует в корректном CSV — обновляются его данные, статус становится «В наличии»;
- товар отсутствует — он не удаляется, его страница и фотографии сохраняются, статус становится «Под заказ»;
- новый `id` — создаётся новый товар, отдельная SEO-страница и карточка в указанном разделе;
- товар снова появился — статус автоматически возвращается на «В наличии».

Пустой, некорректный или резко уменьшившийся фид не применяется.

## Колонки экспорта

Оставить в профиле Битрикса:

| CSV-заголовок | Поле Битрикса | Обязательность | Для чего |
|---|---|---:|---|
| `id` | ID элемента | да | Постоянный идентификатор товара |
| `category` | Название раздела | желательно | Раздел сайта; пустое значение попадёт в «Разное» |
| `name` | Наименование элемента | да | Название товара и SEO |
| `price` | Розничная цена | да | Цена |
| `image` | Детальная картинка (путь) | да для нового товара | Главное фото |
| `article` | Артикул | желательно | Артикул; при отсутствии используется `id` |
| `description` | Краткое описание | желательно | Анонс карточки |
| `description_full` | Детальное описание | желательно | Полное описание товара |
| `images` | Картинки товара `[MORE_PHOTO]` | желательно | Галерея |

Можно удалить:

- `url` — URL товара на старом сайте не используется;
- `stock` — количество не публикуется и для выбранной модели синхронизации не нужно.

В фильтре экспорта оставить «Активность: Да» и «Доступность: Да». Поэтому наличие определяется присутствием товара в CSV.

Заголовки CSV должны оставаться латинскими и точно совпадать с таблицей. Разделитель — точка с запятой, кодировка — UTF-8.

## Проверка вручную

Из локального файла без изменения каталога:

```bash
node sync-products.js --file products_with_descr_images.csv --dry-run
```

Применить локальный файл, пересобрать и проверить сайт:

```bash
node sync-products.js --file products_with_descr_images.csv
node generate-site.js
node verify-build.js
```

## Настройка ссылки на Ubuntu

Секретную ссылку не записывать в Git или JavaScript сайта. Создать закрытый файл окружения:

```bash
sudo install -d -m 750 /etc/rr-tac
sudo nano /etc/rr-tac/feed.env
```

Содержимое:

```bash
BITRIX_CSV_URL='ПОЛНАЯ_ССЫЛКА_НА_CSV'
MIN_FEED_PRODUCTS=1
MAX_MISSING_RATIO=0.5
```

Права:

```bash
sudo chmod 600 /etc/rr-tac/feed.env
```

Проверка ссылки из каталога проекта:

```bash
set -a
. /etc/rr-tac/feed.env
set +a
node sync-products.js --dry-run
```

После успешного теста команда штатного обновления:

```bash
set -a
. /etc/rr-tac/feed.env
set +a
node sync-products.js
node generate-site.js
node verify-build.js
```

Только после успешного `verify-build.js` содержимое `dist/` можно публиковать в корень Nginx. Автоматический таймер следует подключать после первой ручной проверки реальной ссылки.

## Защита от ошибок

- До записи создаётся резервная копия в `backups/`.
- Дубли `id`, пустые обязательные поля и некорректные цены останавливают обновление.
- По умолчанию падение числа доступных товаров более чем на 50% отклоняется.
- Если сильное уменьшение действительно корректно, запуск повторяют с `--allow-large-drop`.
- `--refresh-images` принудительно перекачивает фотографии; обычно он не нужен.
- Относительные ссылки `/upload/...` внутри детального описания автоматически преобразуются в полные ссылки на `https://bready.ru/upload/...`.
