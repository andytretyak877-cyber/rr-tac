Восстановление фотографий 1С-Битрикс
Подготовлено: 4 ноября 2026 года.

Состав
bitrix-upload-photos.zip: 529 непустых фотографий для 60 товаров
с исходными именами и структурой папок upload/iblock/....
bitrix-test-photo.zip: одна фотография для пробного восстановления.
6mdtmy2u570qtabz0t153p4cni92q5sz.jpg: та же пробная фотография отдельно.
manifest.csv и manifest.json: соответствие всех 530 ссылок выгрузки
локальным файлам, исходным путям и SHA-256.

Исключён один пустой локальный файл: rr-56405-1.jpg (товар 56405).
Его исходный путь:
/upload/iblock/914/huu007zi2ieosel9wonqyijjh5hgmelb.jpg
Все 529 включённых файлов повторно сверены по SHA-256 после упаковки.

Когда подходит архив
В базе Битрикса сохранились прежние записи файлов и привязки фотографий,
а исходные файлы отсутствуют на диске. Битые превью сами по себе этого
не доказывают: также возможны ошибки доступа или создания миниатюр.

Пробное восстановление
1. Адрес из сообщения пользователя совпал с путём в старой выгрузке:
   /upload/iblock/980/6mdtmy2u570qtabz0t153p4cni92q5sz.jpg
   Это rr-54337-1.jpg, первое дополнительное фото товара 54337:
   «Аптечка рюкзак тактический с наполнением R9 Rhino Rescue
   20L1000D (мультикам)».
2. В файловом менеджере сервера проверить наличие файла по этому пути.
   HTTP-статус адреса из этой среды проверить не удалось.
   Если оригинал открывается, проверить миниатюры и кэш.
3. Если файл отсутствует, загрузить отдельное пробное фото с исходным
   именем в папку /upload/iblock/980/ основного сайта.
4. Открыть исходную ссылку и проверить карточку товара.
5. После успешной проверки распаковать полный архив и скопировать
   остальные отсутствующие файлы в корень сайта с сохранением структуры
   upload/iblock/.... Существующие файлы пропускать; неработающие файлы
   с совпадающими путями проверять отдельно.
6. При необходимости очистить соответствующий кэш Битрикса для
   формирования миниатюр заново.

Если привязки в базе очищены или изменились, потребуется восстановление
через API Битрикса по проверенным ID товаров.
