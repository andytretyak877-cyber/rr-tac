Запуск от `www-root`:

```bash
cd /var/www/www-root/data/app/rr-tac
node update-reg-ru.js
```

Команда по умолчанию использует сохранённый `assets/data/products.json` и
**не обращается к фиду**; синхронизация требует явного `--sync`. Затем запускает
`generate-site.js`, `verify-build.js`, готовит публикацию, сохраняет `.htaccess`
и `.well-known`, переносит прежнюю публикацию в закрытый `.published-backups/`
и переключает каталог с откатом при ошибке второго rename. Это два rename,
не единая атомарная операция. Резервные публикации занимают примерно 103 МБ каждая.
Автоматический запуск синхронизации товаров не добавлялся.

`--check` выполняет только сборку и проверку. `--no-sync` явно задаёт стандартный
режим без фида. `--sync` разрешает синхронизацию перед сборкой; использовать его
только после восстановления фида и явной настройки `BITRIX_CSV_URL` либо
`FEED_FILE`. В переданной на REG.RU копии `sync-products.js` встроенный адрес
фида очищен; исходный локальный файл и вариант Beget не изменены.

Проверка отказа: запуск с `--sync` и недоступным localhost URL завершился ошибкой;
