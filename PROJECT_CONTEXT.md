## Архитектура

Проект остаётся статическим: Vanilla HTML, CSS и JavaScript. PHP не используется для рендеринга страниц.

Исходные данные:

```text
products_with_descr_images.csv
  -> csv-to-json.js
  -> assets/data/products.json
  -> generate-site.js
  -> dist/
```

`dist/` — готовая публикационная сборка. На сервер загружается содержимое `dist`, а не исходники проекта.

### Обязательный секрет Roistat при публикации

Ключ Roistat не входит в `dist` и не отслеживается Git. Перед первой заменой файлов из `dist` необходимо сначала отдельно разместить локальный файл `config/roistat.php` на сервере по адресу:

```text
/var/www/html/config/roistat.php
```

Рекомендуемые права:

```bash
chown root:www-data /var/www/html/config/roistat.php
chmod 640 /var/www/html/config/roistat.php
```

После этого обычные загрузки `dist` и автоматическое обновление товаров файл не перезаписывают. Если отправка формы или передача лида в Roistat перестала работать, первая проверка: существует ли `/var/www/html/config/roistat.php` и может ли пользователь `www-data` его прочитать. При полной очистке `/var/www/html` конфиг нужно восстановить до публикации `dist`.

Сгенерированные URL:

```text
/
/catalog/
/catalog/{category-slug}/
/product/{product-id}/
/cart/
/delivery/
/payment/
/about/
/contacts/
```

Сейчас генерируется:

- 60 товарных страниц;
- 14 страниц категорий;
- общий каталог;
- 81 URL в `sitemap.xml`.

## Основные команды

Сборка:

```bash
node generate-site.js
```

Проверка:

```bash
node verify-build.js
```

Генератор по умолчанию использует `https://rr-tac.ru`. При необходимости домен можно переопределить:

```bash
SITE_URL=https://example.ru node generate-site.js
```

PowerShell:

```powershell
$env:SITE_URL = "https://example.ru"
node generate-site.js
```

## Важные файлы

- `generate-site.js` — статическая генерация страниц, SEO, sitemap, robots и cache-busting.
- `verify-build.js` — проверка страниц, метатегов, H1, canonical и внутренних ссылок.
- `csv-to-json.js` — преобразование CSV и загрузка изображений.
- `assets/data/products.json` — текущая база из 60 товаров.
- `assets/js/main.js` — общий интерфейс, анимации и форма заявки.
- `assets/js/catalog.js` — только поиск, фильтр наличия и мобильная панель. JSON не загружает и карточки не перерисовывает.
- `assets/js/product.js` — галерея, lightbox, количество и добавление в корзину на статической странице товара.
- `assets/js/cart.js` — корзина в localStorage; исправляет старые относительные пути изображений.
- `assets/js/home.js` — блок популярных товаров на главной.
- `assets/css/style.css` — общие стили и обе темы.

## SEO

Все страницы имеют уникальные Title, Description и canonical. На каждой странице ровно один H1.

Главная:

```text
Title: Rhino Rescue — интернет-магазин тактической медицины | RR-TAC
H1: Rhino Rescue
H2: Товары тактической медицины
```

Главный бейдж:

```text
Официальный дистрибьютор Rhino Rescue в России
```

Категории используют шаблон:

```text
[Название категории] Rhino Rescue — купить, цены | RR-TAC
```

Товары используют название, наличие, цену и артикул. Генератор не добавляет Rhino Rescue повторно, если бренд уже есть в названии. Длинные Title сокращаются с сохранением уникальности через артикул.

Микроразметка:

- `Product` + `Offer` + `Brand` для товаров;
- `BreadcrumbList` для товаров и категорий;
- `CollectionPage` + `ItemList` для категорий;
- `WebSite` для главной.

Корзина имеет `noindex, follow`.

## Анимации и производительность

Анимации `.reveal`, `.reveal-left`, `.reveal-right` обязательны — это важная часть дизайна.

Категории уже содержат карточки в HTML. Нельзя возвращать загрузку всего `products.json` и повторный рендер каталога: это вызывало спиннер и заметную задержку.

Первые карточки получают каскадные классы `reveal-delay-*`. `main.js` активирует их через `IntersectionObserver`.

Генератор добавляет хеш версии к CSS и JS:

```text
/assets/css/style.css?v={hash}
/assets/js/catalog.js?v={hash}
```

Это предотвращает загрузку старого кода из кеша после публикации.

## Формы

Email обычных заявок отправляется через отдельный SMTP-обработчик:

```text
/assets/php/mail.php
```

Roistat отправляется независимо через `/assets/php/send.php`. Оба запроса запускаются параллельно: успех SMTP или Roistat считается успешной отправкой формы. Заказы используют `/assets/php/order.php`, где попытка SMTP выполняется после попытки МойСклад и не отменяет уже подтверждённый заказ.

PHPMailer читает настройки из `/var/www/config/mail.php`. Реальный файл находится вне web-root, Git и `dist`; в репозитории хранится только `config/mail.example.php` без пароля.

## Nginx

Корень сайта:

```text
/var/www/html
```

Содержимое `dist/` распаковывается непосредственно в `/var/www/html`.

Важно: до распаковки новой версии `dist` файл `/var/www/html/config/roistat.php` уже должен существовать. Он переносится отдельно и не содержится в архиве сборки.

Для статических ЧПУ используется:

```nginx
location / {
    try_files $uri $uri/ $uri/index.html $uri.html =404;
}
```

Старые rewrite на `catalog.php` и `product.php` не используются.

PHP-FPM 8.3:

```nginx
fastcgi_pass unix:/var/run/php/php8.3-fpm.sock;
```

PHP рекомендуется разрешать только для `/assets/php/send.php`.

Права на сервере:

```bash
sudo chown -R www-data:www-data /var/www/html
sudo find /var/www/html -type d -exec chmod 755 {} \;
sudo find /var/www/html -type f -exec chmod 644 {} \;
```

## Обновление каталога из 1С-Битрикс

Добавлен `sync-products.js`. Он загружает CSV из `BITRIX_CSV_URL` или читает локальный `--file`, проверяет его и обновляет накопительный каталог:

- строка есть в фиде — «В наличии»;
- строка исчезла — товар сохраняется как «Под заказ»;
- новый `id` — новый товар и отдельная SEO-страница;
- перед записью создаётся резервная копия;
- пустой, повреждённый или подозрительно маленький фид отклоняется.

Полная инструкция и список колонок: `FEED_UPDATE.md`.

Штатный конвейер:

```text
скачивание CSV
-> проверка структуры и количества товаров
-> резервная копия
-> sync-products.js
-> generate-site.js
-> verify-build.js
-> атомарная публикация dist
```

Ссылку Битрикса хранить в переменной окружения `BITRIX_CSV_URL`, а не в коде. Автоматический systemd timer подключать только после ручной проверки реального URL.
